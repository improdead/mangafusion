STARTUP SEQUENCE:
----------------

Development:
1. Start Redis: docker run -d -p 6379:6379 redis:alpine
2. Set REDIS_URL in .env
3. Terminal 1: npm run dev (API)
4. Terminal 2: npm run worker:generate (Worker)

Production:
1. Ensure Redis is available
2. Build: npm run build
3. Start API: node dist/main.js
4. Start Worker: node dist/worker/generate.worker.js
   (Use PM2 or systemd for process management)


FALLBACK BEHAVIOR:
-----------------

When REDIS_URL is NOT set:
- Queue is disabled
- Uses in-process generation (original behavior)
- No worker process needed
- SSE events work via direct EventsService


BACKWARD COMPATIBILITY:
----------------------

✅ 100% compatible with existing codebase
✅ No breaking changes to API
✅ In-process fallback when Redis unavailable
✅ Existing SSE streaming unchanged
